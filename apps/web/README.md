# 课堂小工具 Web

`apps/web` 是一个基于 Next.js 16、React 19 和 Zustand 的桌面式课堂工具箱。应用以可拖动、最小化和聚焦的多窗口形式运行，移动端使用适配后的窗口布局。

### 学期报告入口

学期报告与学科报告的预览、家长分享页和导出图片，仅在填写教学内容正文时显示「课程内容」板块。正文未填或仅含空白时，即使有出勤、授课范围或后续教学重点也隐藏整个板块；已保存的数据保留。

从桌面或应用菜单打开「学期报告」。进入「课程资料」选择学期和学科后，可上传最多 30 MB 的 PDF，等待后台解析并核对章节，再在「填写报告」中引用课程内容。「学期报告工作台」有独立入口。

### 学科报告工作台

报告管理列表按「学生姓名 · 班级」显示。草稿提供「预览/微调」和「发布」，已发布报告提供「查看流程」「报告图片」「撤销」和删除操作；家长链接与复制按钮单独显示在卡片下方，与学期报告工作台一致。点击「查看流程」与学期报告工作台保持一致，唤起报告内容与流程弹窗，呈现已发布状态徽章、1:1 家长端实时长图镜像与课程、出勤及评价明细，提供「关闭」按钮和 Escape 键盘关闭支持。在报告管理中点击「编辑草稿」，可在「报告抬头与课程」下修改或清空每节课的课程内容。点击「添加课程」会新增与新建报告相同的四项课程内容及出勤，旧草稿的自由文本可在「原有课程内容」中编辑，删除课次会一并移除对应内容。可展开「从课程 PDF 填入」，选择该报告学期和学科下已确认的 PDF 章节，或输入页码带入正文。切换范围会更新空字段和上一次带入且未手动修改的字段。保存草稿或发布后会使用修改后的正文。报告按课次分别显示教学内容与对应出勤。未填写的学习习惯与能力成长模块会隐藏；生成时保存学生头像、周期截止宠物形态及周期加分细项统计。

从桌面打开「学科报告」。在「学期学科设置与课程资料」新增学期、学科或维护课堂表现选项。学科设置中可切换所属学期，新建学科直接与当前选定学期绑定（`termId`），学科列表、课程资料与课堂表现配置切换均按所选学期过滤，并兼容历史无学期的全局学科；学科设置与学期报告工作台各自独立，教师在学科报告中新增、停用或配置学科仅在学科报告工作台生效，不会影响学期报告工作台的学科列表与配置；点击学科旁的删除按钮并确认后，该学科会从学科报告新建选项中移除，已有报告及已上传 PDF 资料会保留。选择学期和学科后上传最多 30 MB 的 PDF，上传期间锁定选择，成功提示显示归属，待解析后核对章节。停用学科后，已有学科报告草稿仍可按原学期和学科引用已确认的 PDF。填写报告时只选择一门学科（按当前向导所选学期动态过滤），每节课可从完整的章节下拉列表切换章节，或在独立输入框填写页码带入教学内容，切换章节或页码会更新 PDF 带入的字段，已有手填或手动修改的字段会保留。课堂反馈使用该学科的评价选项。

填写向导采用四步流程：1. 周期与基础 -> 2. 选择学生 -> 3. 学科与内容来源 -> 4. 课堂评价与生成。学科报告通过「生成报告」创建草稿，可在报告管理中继续编辑。生成成功后清空本次手填内容、PDF 带入内容、章节页码和学生评价，再次新建从空白表单开始。课程资料库中的 PDF 可重新选择。新建学科报告默认选中周报，起止日期为本周周一至周五，可手动调整。在第二步挑选本次生成报告的学生（支持班级筛选与全选本班），在第三步选择学科并填写课次教学内容、授课范围与「下周课堂预习内容」（按周期自适应为下月/下学期预习内容）。第四步课堂评价通过左侧名单逐人切换，提供周期积分和宠物形态预览、学科评价、快捷寄语、「回家可以跟父母一起练」（原下一步重点，支持添加最多 8 条建议）及逐人完成进度；学科报告新增向导与草稿编辑均去除“学习习惯与能力成长总结”模块。评价后点击「保存并切换下一位学生」，提示已暂存当前学生反馈并切换到下一位；最后一位完成后提示确认生成草稿，与学期报告工作台一致。设置页上方并排显示学期与学科设置和课程资料，下方的「配置学科课堂表现」与学期报告工作台共用编辑器。选择学科后可新增或删除评价维度、编辑预设选项，每行一个选项，点击「保存课堂表现配置」后生效。切换学科前请先保存。点击虚线 PDF 上传区或用键盘聚焦后选择文件。

生成前在课堂评价中可逐位、逐课次选择每次课程的出勤状态（如第 1 节课、第 2 节课等），默认「出勤」，也可选「请假」或「迟到」。草稿编辑弹窗支持查看、修改各课次出勤，并可通过「+ 增加课次出勤」或删除按钮增删课次出勤记录。家长报告和长图会按课次完整展示出勤状态与教学内容，单科课堂表现占满一行。

「报告管理与分发」支持学科、周期、状态、日期及关键词筛选。选中草稿后可批量发布，选中已发布报告后可导出长图 ZIP。

### 学期报告工作台全新特性

- **独立版本入口**：通过桌面或顶部应用菜单以 `contentKey: "semesterReportStudio"` 直接进入“学期报告工作台”，完全不修改、不影响原版“学期报告”与“学期报告 v2”原有界面；
- **100% 还原原型 4 标签交互**：主界面统一为【报告管理与分发】、【填写与生成报告 (向导)】、【AI 阶段汇总 (定时任务)】、【学期学科设置与课程资料】4 大标签切换；
- **AI 阶段汇总定时任务与服务端离线守护**：班级与学生范围严格来自当前教师的数据，支持全班、指定班级和跨班自由勾选；阶段周期提供“近 1 月”、“本学期”与“自定义”三项预设，具备清晰高亮切换与自适应日期同步；支持在任务创建时输入**自定义阶段称谓**（如“10月份”、“期中阶段”），自动将报告正文、总结、维度以及标题中的“本阶段”文字全局替换为该自定义称谓；支持配置“单次执行”、“每周重复”与“每月重复”循环调度模式，阶段结束日与云端执行日自动对齐；任务默认以列表展示，调度与前端会话解耦，教师关闭浏览器或离线后仍按计划生成草稿并自动顺延下一周期；生成阶段报告时严格限定仅读取时间段内的已发布/草稿周报，生成学期报告时仅读取时间段内的各阶段汇总报告；
- **全量学生花名册实时多源聚合**：在报告填写与 AI 阶段汇总任务选择学生时，自动并行聚合学生管理班级花名册与宠物积分学生数据，新增入班或新导入学生无需进入宠物模块手动同步即可即刻在学期报告及 AI 阶段汇总的学生列表中展示与勾选；
- **草稿直接沉淀至主管理视图**：AI 生成的阶段汇总报告统一以 `draft`（待发布草稿）状态直接存入【报告管理与分发】主视图，无需在 AI 标签页内进行二次重复审核；主列表提供「✨ AI 阶段报告」快速筛选胶囊与标识徽章；
- **阶段任务学生级进度**：任务执行期间按已完成学生数展示进度条；全部学生完成 Kimi 生成或默认数据兜底后，才显示“前往报告管理查看”。任务卡片使用创建时冻结的所选学生姓名，避免内部学生 ID 兼容映射导致名单错位；
- **排队多任务全生命周期管理**：定时任务队列展示倒计时状态，支持对任务进行随时编辑修改时间点与挑选学生、立即手动提前执行或取消移除；
- **报告版面与生成规则 1:1 保持一致**：AI 阶段报告的预览微调弹窗、成长评价四维度（学习准备、人际交往、规则意识与整体领悟）、课堂表现胶囊、宠物快照及家长端 1:1 生成长图与手动创建的周报/学期报告结构完全一致；
- **学科与学期多对一绑定**：「学期学科设置与课程资料」中的学科设置支持选择所属学期，新增学科时直接保存绑定的学期；向导步骤 2（涉及学科与教学内容来源）严格按选定学期过滤展示学科，仅显示属于该学期或未指定学期的存量兼容学科，避免跨学期学科冗余；
- **内嵌式整班生成向导与真实积分展示**：生成向导直接内嵌在主视图（非弹窗阻断），涵盖基础周期、学科与教学内容来源配置（默认不选学科，未选学科时禁用并禁止进入下一步）、自主勾选学生名单（新增报告时不默认全选学生，支持单选与按班级一键全选/清空；学生卡片呈现真实分值或 `0分`，杜绝原型假象分值），以及多学生快速切换批阅工作台；手动填写的周报（`week`）走本地模板确定性秒级生成，不调用大模型生成也不消耗 Token；只有走 AI 阶段汇总时才调用大模型请求 AI；
- **各科课堂表现纯单选评价**：课堂表现评价严格限制只能单选设置好的预设值，彻底禁止手动文本输入；支持胶囊点击高亮、再次点击取消反选及“暂不评价”快捷清空；
- **双栏草稿微调与 1:1 实时长图**：左侧提供草稿微调（调整学科至少保留 1 门、各科课堂表现仅预设单选、照片上限 2 张 2MB、重点建议上限 8 条等），右侧 1:1 实时镜像联动家长端最终长图，支持嵌入式版本历史对比与一键还原；
- **周期积分动态核对与最值肯定**：向导第 4 步与草稿微调联动 `/api/semester-reports/reports/preview-input` 接口，按所选周期动态读取各学生在周期内的正向加分事件细项与宠物快照，自动渲染为【本周/本月/本期最值肯定】柱状图，并在生成与保存草稿时无损写入报告 `scoreDetails`；
- **可靠弹窗与既有数据查看**：模态弹窗具备遮罩点击关闭、Escape 键关闭、右上角关闭按钮和底部关闭按钮；批量发布与删除采用项目内 `ConfirmDialog`（绝不调用原生浏览器弹窗）；全量支持加载并查看所有历史/既有报告数据。

桌面窗口状态由 `store/windowStore.ts` 管理；计时器（含倒计时与正计时）等跨窗口状态使用独立 Zustand Store。功能打开事件会通过认证后的 `/api/analytics/events` 上报，供管理端展示聚合统计。

## 本地运行

在仓库根目录安装依赖后执行：

```bash
pnpm --filter ClassRoomToolkitWeb dev
```

开发服务默认监听 `http://127.0.0.1:3001`。启动脚本会记录 Next.js 子进程，并在退出时清理服务和 `.next/dev/lock`。

如不希望自动打开浏览器：

```bash
OPEN_BROWSER=0 pnpm --filter ClassRoomToolkitWeb dev
```

## 服务端配置

| 变量                      | 用途                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------- |
| `BACKEND_URL`             | Next.js BFF 在运行时访问的 Backend 根地址；生产环境必填，例如 `http://backend:3000`。 |
| `LOGIN_PROXY_SECRET`      | Web 与 Backend 共用的服务端随机密钥，用于可信转交入口代理提供的登录 IP。              |
| `NEXT_PUBLIC_BACKEND_URL` | 仅开发环境的后端地址回退值；生产环境不会用它替代缺失的 `BACKEND_URL`。                |
| `AUTH_COOKIE_SECURE`      | 显式控制教师 Cookie 的 `Secure` 属性；未设置时根据请求协议或代理协议自动判断。        |

`BACKEND_URL` 仅在 Next.js 服务端读取，不应暴露数据库或密钥。生产部署应使用 HTTPS，并让反向代理正确覆盖 `X-Forwarded-Proto`。

## 代码检查

```bash
./node_modules/.bin/tsc -p apps/web/tsconfig.json --noEmit
./node_modules/.bin/eslint apps/web/app apps/web/components apps/web/lib apps/web/store apps/web/types
```

桌面入口和应用路由位于 `app/page.tsx`，业务组件位于 `components/apps/`。同源 BFF 路由位于 `app/api/`，负责教师 Cookie、Bearer Token 转发、上传大小限制和后端异常转换。

## 教师登录与退出

浏览器只保存由 Next.js BFF 设置的 `HttpOnly`、`SameSite=Lax` 教师会话 Cookie，不在客户端 JavaScript 中保存后端 Token。登录、注册和教师业务请求统一通过同源 `/api/*` 路由访问 Backend。

退出登录时，`POST /api/logout` 会请求 Backend 撤销服务端会话，并始终清除浏览器认证 Cookie。撤销请求最多等待 1.5 秒；Backend 连接失败或超时不会阻止本地退出，遗留的服务端会话会按后端过期时间自动失效。

认证失败的常见状态：

- `400`：账号、密码或其他输入的类型、空值、长度不符合要求。
- `401`：账号密码错误，或现有会话已经失效。
- `429`：同一来源对同一账号的尝试过于频繁，需要稍后重试。

### 登录来源转发

与 Backend 配置相同的服务端 `LOGIN_PROXY_SECRET`，入口 Nginx 用 `proxy_set_header X-Real-IP $remote_addr` 覆盖来源头，并限制 Web 端口仅允许可信入口访问。登录与注册 BFF 将来源 IP 交给 Backend，用于登录分析与封禁判断。密钥不得使用 `NEXT_PUBLIC_` 前缀。被封 IP 登录或注册时页面显示“禁止账号登录，请联系管理员解封”；解封由 Admin 登录分析页执行。

IP 封禁也适用于已有 Web 会话：仅在发送请求时校验，命中时撤销当前令牌并清除 Cookie；空闲页面和切回标签页不主动校验。退出后只显示“禁止账号登录，请联系管理员解封”。管理员认证不受影响，网络故障不会误判为封禁。

### AI 阶段汇总任务队列实时推送 (SSE)

在学期报告 V2 的【AI 阶段汇总定时任务中心】中，前端完全废除传统的 `setInterval` 轮询请求，改用 `EventSource` 与后端建立 Server-Sent Events 流式通信：

- BFF 流式透传：Next.js `backend-proxy.ts` 自动识别 `text/event-stream` 内容类型，直接将后端响应流（ReadableStream）直传返回，并禁用响应缓冲（`X-Accel-Buffering: no`）。
- 实时同步：前端页面挂载后订阅 `/api/semester-reports/scheduled-tasks/stream`，接收初始任务快照以及后续任意任务状态变化（新建、立即执行、后台 Worker 生成进度推进、任务完成或降级），毫秒级自动刷新任务卡片与学生执行进度条。
- 自动重连与降级：利用浏览器 原生 `EventSource` 的自动重连机制，当环境不支持 SSE 时自动降级为单次请求，保证兼容性与鲁棒性。

学科报告设置支持按学科新增、编辑、删除课程内容标题，点击「保存课程内容标题」后用于新建报告。最多 12 项，每项 1–40 字，不得重复或包含冒号、换行；可删除全部标题，历史报告正文保留。接口 `PATCH /subject-reports/report-subjects/:id/course-content-titles` 接收 `courseContentTitles: string[]`，仅操作当前教师的启用学科。部署先运行常规结构迁移以新增可空 JSON 列，不回填或改写已有业务数据。

学科报告「学期学科设置与课程资料」提供学期删除按钮，确认后仅停用共享学期，两个报告工作台的新建学期选项同步移除；已有报告、公开分享、草稿编辑与发布、课程资料均保留。删除失败时保留选项供重试。`DELETE /subject-reports/report-terms/:id`（及学期报告同名接口）仅允许操作当前教师的学期，无权访问或不存在返回 404，重复删除成功。部署前运行常规结构迁移，新增 `semester_report_terms.enabled`，默认启用；不执行数据回填，回滚代码保留停用状态列。

学科报告设置中的「学科设置」与「学期设置」分卡显示。学期删除入口位于「既有学期日历」对应学期及起止日期旁，不与学科列表混排。

学期报告工作台的学科设置、学期设置分卡显示，各项旁均可删除并通过项目弹窗确认。学科删除仅作用于学期报告工作台，`DELETE /semester-reports/report-subjects/:id` 按当前教师停用学科（不存在或无权访问返回 404）；学期删除共用既有停用接口。删除保留报告、分享与课程资料，失败保留选项；新增设置使用服务端返回的真实 ID，成功返回空列表时不再自动补示例项。无额外结构迁移或业务数据回填。

功能使用统计已独立注册「学科报告」（`subject-reports`）。教师打开学科报告工作台记录打开事件；新版学期报告入口 `semesterReportStudio` 与旧版入口统一计入「学期报告」。Admin「功能使用」按功能分别显示打开教师数、使用教师数、成功操作次数及每日趋势，零事件时仍显示功能。使用次数仅由成功的服务端已标记业务操作产生（如生成、保存、发布和分享），客户端不能伪造 use 事件；后台刷新及家长查看不计入。仅补齐统计映射，无数据库迁移或历史事件回填；已有合法操作事件会自然进入查询范围，漏记的历史打开事件无法补算。

学科报告工作台草稿编辑支持上传与删除课堂照片（每份报告上限 2 张，单张限制 2MB）：

- **编辑弹窗交互**：草稿编辑弹窗（`DraftEditModal`）支持选择第 1 张与第 2 张课堂照片上传或删除，并在右侧 1:1 预览中即时联动更新。
- **动态路由与 BFF 容错**：编辑弹窗根据报告类型动态调用 `/api/subject-reports/reports/:id/classroom-photo`；Next.js API 代理同时对旧请求进行 transparent fallback，若向 `/api/semester-reports/.../classroom-photo` 请求返回 404，会自动克隆请求流重试 `/subject-reports`，避免未刷新页面的存量标签页报错。
