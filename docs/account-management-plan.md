# 主账号与子账号管理方案

日期：2026-10-12。分支：`featuer/account-management`，从 `main` 创建。

状态：已按本文默认口径实现。主子账号共享主账号业务数据，两个学期报告共用配置权限边界。

## 1. 需求范围与建议口径

- 所有自行注册的账号为主账号，已有账号兼容为主账号；主账号最多创建 5 个未删除的子账号，锁定账号仍占名额。
- 创建子账号填写「用户名（显示姓名）」「账号（登录标识）」「密码」。为兼容现有认证，数据库 `name` 保存显示姓名，`username` 继续保存登录标识；界面明确区分两者。
- 主账号可修改子账号显示姓名、重置密码、锁定/解锁、删除。建议登录标识创建后不可修改；不支持子账号再创建子账号或账号转移。
- 子账号可使用其他全部功能，但不显示账号管理入口，直接访问页面或接口也被拒绝。
- 「两个学期报告」按原版与 v2 理解；子账号不能创建学期、学科，不能新增或修改学科课堂表现项目及选项，但可选择已有配置、为学生填写课堂表现、新增与修改报告。
- 报告流程显示实际操作账号当时的显示姓名；改名或删除账号不会改变历史记录。
- Admin 可查看主子关系、账号状态与使用习惯；主账号只可查看自己子账号的使用情况。

以下默认口径已按“根据文档进行开发”的指令采纳：

1. 主子账号共享主账号下的所有业务数据（学生、班级、积分、学期、学科、报告等），子账号之间可见并操作同一数据。若需要各自独立数据或按班级授权，需要另行设计，不能只隐藏页面。
2. 学期报告权限仅限制基础配置维护；子账号仍可按当前功能发布、分享、删除报告、恢复版本，以及在草稿中选用已有学科。子账号上传原版课程资料仍允许，但不能借上传、导入或其他入口隐式创建基础配置。
3. 删除采用软删除，释放名额，保留报告、操作记录与统计；建议被删除账号的登录标识不复用，避免身份混淆。
4. 「习惯」指客观使用统计：最近登录、活跃天数、登录频次、常用功能、使用次数、常用时段与报告操作量。本期不统计在线时长，不推断个人性格或教学效果。

## 2. 当前实现与改造边界

- Backend 现有 `teacher-auth` 使用独立账号和会话，`TeacherContext.teacherId` 直接取登录账号 ID，多数业务据此隔离数据。
- `teacher_auth_teachers.username` 已有唯一约束，`name` 是显示姓名，已有密码盐与哈希机制可复用。
- 报告事件已有操作、时间、版本及中文变化详情，没有实际操作人字段；后台 Worker 的事件也需要明确标记系统行为。
- `analytics_events.teacherId` 与统计拦截器当前记录实际登录账号。Admin 已有教师列表、详情、登录及功能使用统计，可以扩展。
- Web 原版和 v2 当前共用 `semester-reports` 统计标识；需要增加版本维度才能分别统计，旧数据不强行猜测版本。

核心改动是区分「数据归属」与「实际操作者」，不能把所有统计中的账号 ID 替换为主账号 ID。

## 3. 数据结构与身份上下文

### 账号与会话

扩展 `teacher_auth_teachers`：

| 字段                                | 用途                                                            |
| ----------------------------------- | --------------------------------------------------------------- |
| `parent_account_id`（可空，带索引） | 空为主账号；子账号只关联一个主账号，不允许多级关系              |
| `status`                            | `active / locked / deleted`                                     |
| `deleted_at`（可空）                | 软删除时间                                                      |
| `session_version`                   | 重置密码、锁定/解锁、删除时递增，阻止并发旧登录在状态变化后落库 |

账号类型由父账号关系派生，避免同时维护角色与关系产生冲突。已有 ID、登录标识、姓名、密码与创建时间保留。

认证响应在原有字段上增加 `accountType`、`ownerAccountId`、`capabilities`。服务端每次认证读取最新账号与父账号状态，不能信任客户端角色和 owner ID。

身份上下文明确提供：

- `actorAccountId`：当前登录账号 ID，操作审计和统计使用该值。
- `ownerAccountId`：主账号 ID，业务数据查询和写入使用该值。
- `actorDisplayName`、账号类型与服务端权限集合。

为保留旧数据，现有业务表 `teacher_id` 继续存主账号 ID；现有 `TeacherContext.teacherId` 可兼容为 owner ID，并添加明确的 owner/actor 访问器。开发前逐个核对直接使用 `request.teacher.id` 的模块、Worker、学生 ID 前缀及缓存，避免绕开归属过滤。

### 审计与统计

- 报告事件新增可空 `actor_account_id`、`actor_name_snapshot` 和 `actor_type`（主账号/子账号/系统/历史未知）。创建、编辑、重新生成、发布、分享、删除与恢复都记录实际操作者；生成任务保存发起人，Worker 完成事件显示「系统生成」，可关联发起人，不冒充人工编辑。
- 新增账号管理审计记录：归属主账号、操作者、目标账号、动作、时间及必要变更摘要。不得写入密码、密码哈希或令牌。
- `analytics_events.teacherId` 保持实际账号口径，增加可空 `owner_account_id` 与报告版本维度；按 owner 聚合时返回总量和逐子账号明细。历史事件中已知教师 ID 可以回填 owner，未识别事件保留未知。
- 报告旧事件没有可靠操作者时显示「历史记录（未记录操作人）」；不将数据归属人伪造为编辑人。

## 4. 权限与业务规则

| 操作                             | 主账号                   | 子账号               |
| -------------------------------- | ------------------------ | -------------------- |
| 账号管理页面及相关接口           | 允许，只管理自己的子账号 | 拒绝                 |
| 创建/维护学期与学科              | 允许                     | 拒绝                 |
| 新增/修改课堂表现项目、选项      | 允许                     | 拒绝                 |
| 查看、选择已有学期/学科/评价选项 | 允许                     | 允许                 |
| 新增/修改报告及填写学生评价      | 允许                     | 允许                 |
| 报告其他操作                     | 按现有能力               | 按现有能力           |
| 其他业务功能                     | 允许                     | 允许，共享主账号数据 |
| 查看子账号使用情况               | 自己名下                 | 拒绝                 |
| Admin 数据及统计                 | 仅独立管理员身份可用     | 不能通过教师身份访问 |

- 前端按 capabilities 隐藏入口和配置编辑区域；后台以统一权限检查作为真正边界，原版与 v2 使用相同规则。导入、草稿保存、历史恢复、资料上传等间接入口不能修改基础配置。
- 基础配置仅主账号可写，包括以后新增的修改、删除或批量接口；报告正文中的评价填写和选用已有学科不属于修改基础配置。
- 创建子账号使用事务锁定主账号行，统计未删除子账号后插入；第 6 个返回明确额度错误，并发创建也不能突破 5 个。账号唯一性以数据库约束为最终依据。
- 所有目标账号必须校验父账号关系；不能把主账号作为子账号删除或通过传 ID 管理其他家庭/团队。
- 重置密码、锁定、删除与会话撤销在同一事务完成；密码重置后要求重新登录。解锁不能恢复旧会话。后续请求重新检查状态，后台异步任务仍保留原发起人；已提交且成功排队的任务建议继续执行。
- 删除只终止账号访问，业务数据和已发布报告/分享链接保留。操作人历史快照保留。危险操作使用项目弹窗，支持可见取消/关闭、Escape、焦点恢复和窄屏布局。
- 同一报告的并发编辑使用服务端 `currentVersion`，公开草稿保存接口要求提交 `expectedVersion`；缺少版本返回 400，保存冲突返回 409 并保留本地输入，防止主子账号相互覆盖。其他报告操作及历史恢复沿用事务锁。
- 登录会话创建在事务中按主账号、实际账号的顺序加锁，并核对密码哈希及会话版本。重置或锁定/解锁期间已通过旧密码校验但尚未落库的登录会被拒绝；Admin 重置密码也递增会话版本。

## 5. 页面与接口草案

### Web 账号管理

主账号工具入口增加「账号管理」，包括：

- 名额提示，例如「已创建 3/5 个子账号」，锁定计入名额。
- 子账号列表：显示姓名、登录账号、状态、创建时间、最近登录，以及编辑姓名、重置密码、锁定/解锁、删除按钮。
- 新建/编辑表单校验，提交期间防重复；失败保留非敏感输入，密码不长期保存在浏览器，成功不展示原密码。
- 每个子账号的「使用情况」详情：日期范围、登录和活跃概况、功能排行、使用时段、报告操作量与最近操作。
- 手机使用卡片和详情页，避免必须横向滚动才能操作。子账号直接打开账号管理页面时显示无权限并提供返回入口。

账号切换或登录态失效时清理原有业务缓存、窗口和持久状态；缓存键显式包含 owner/actor 范围，避免同浏览器跨主账号显示旧数据。

拟定 Backend 接口，Web 通过现有代理模式接入：

| 接口                                                                     | 含义                                          |
| ------------------------------------------------------------------------ | --------------------------------------------- |
| `GET /account-management/subaccounts`                                    | 列表、状态、额度                              |
| `POST /account-management/subaccounts`                                   | 创建，输入 `displayName / account / password` |
| `PATCH /account-management/subaccounts/:id`                              | 修改 `displayName`                            |
| `POST /account-management/subaccounts/:id/reset-password`                | 重置密码                                      |
| `PATCH /account-management/subaccounts/:id/status`                       | 锁定/解锁                                     |
| `DELETE /account-management/subaccounts/:id`                             | 软删除，可重复调用                            |
| `GET /account-management/subaccounts/usage-summary?start=&end=`          | 主账号与全部子账号使用汇总                    |
| `GET /account-management/subaccounts/activity-summary?start=&end=&page=` | 主子账号报告操作汇总                          |
| `GET /account-management/subaccounts/:id/usage?start=&end=`              | 使用概况与趋势                                |
| `GET /account-management/subaccounts/:id/activity?start=&end=&page=`     | 分页操作记录                                  |

这些接口统一要求主账号身份和目标归属，不接受客户端指定 owner。姓名建议 1—64 字、账号沿用现有 64 字上限及统一规范化规则、密码至少沿用当前 6 位要求；开发时明确完整账号字符及大小写规则，迁移前检查历史冲突，不擅自更改旧账号。

错误规则：输入不合法 400；会话失效/锁定/删除 401；子账号调用主账号接口 403；目标不存在或不属于当前主账号 404；账号冲突、额度已满或报告版本冲突 409。列表和统计失败提供重试；修改失败不显示成功，保留可重试输入。锁定等操作完成后刷新状态，避免旧缓存仍显示可登录。

### 学期报告流程

原版和 v2 都隐藏新建学期、学科及配置课堂表现入口，保留已有选项与报告编辑能力。主账号未配置时显示「请联系主账号创建学期、学科及课堂表现配置」。

流程记录示例：「张老师（子账号） · 编辑报告草稿 · 2026-10-12 14:30」。展示事件发生时的姓名，账号更名后保持原记录；已删除账号在账号管理列表中标记，报告流程继续保留当时姓名。编辑人仅在内部流程展示，家长分享页不新增账号或使用统计信息。

### Admin

在现有教师列表/详情中扩展账号类型、父账号、状态与子账号数量，支持类型、主账号、状态筛选和按姓名/登录账号搜索。主账号详情展示子账号清单，子账号详情提供返回所属主账号的链接。

扩展现有 `/admin/teachers`、`/admin/teachers/:id` 及 analytics 查询，增加 `accountType / ownerAccountId / status` 筛选；详情提供 `subaccounts` 和统计范围。沿用独立 Admin 认证与权限，不把教师主账号当管理员。

Admin 可以分别查看「注册主账号数」「创建子账号数」「账号总数」，不把创建子账号计入公开注册人数；学生和班级属于 owner，不能给每个子账号重复计数。现有密码重置需适配子账号状态与会话撤销。本期不额外增加 Admin 批量删除能力。

## 6. 使用情况统计口径

- 支持近 7 天、近 30 天和自定义范围；统计事件按现有 UTC 规则查询，页面按 Asia/Shanghai 展示日期和小时；历史教师及报告事件时间按 `TEACHER_DATA_UTC_OFFSET` 转换。
- 主动登录、注册后自动登录、失败登录分开计数；仅刷新页面不算一次主动登录。
- 活跃天数以发生有效功能使用的日期去重；打开次数与成功使用次数分开，后台轮询不算使用，失败操作不计成功次数。
- 常用功能按成功使用事件排序；常用时段为有效使用事件按小时分布。报告生成按一次被接受的批量请求计数，生成报告份数独立统计，不把 Worker 重试当人工使用。
- 审核各功能现有埋点覆盖，补齐真正有业务意义的成功操作；报告编辑记录依服务端事件，客户端不能伪造成功使用或编辑人。
- 主账号只看到自己名下数据，已删除子账号历史可按状态筛选。账号管理安全审计必须持久化，普通热度埋点沿用尽力写入；统计缺失不伪装为精确监控。
- 原版/v2 新事件分别统计，旧事件展示为版本未知；暂无数据时显示暂无记录，不把缺失数据当成不使用。

## 7. 开发顺序与验收计划

建议分四步交付，每步同步设计、实现和对应测试：

1. 数据迁移、主子关系、身份上下文、状态检查与会话失效；先完成跨主账号隔离测试，再调整业务 owner 范围。
2. 子账号管理接口与 Web 页面、5 个额度事务、密码/锁定/软删除审计。
3. 两个报告版本的基础配置权限、编辑人快照、异步发起人及并发编辑冲突。
4. 主账号使用情况与 Admin 主子关系、统计口径、全链路验收。

关键回归必须覆盖：

- 旧账号升级仍可登录、数据不变；注册始终创建主账号，不能通过注册参数自选子账号角色。
- 创建 1—5 个、第 6 个失败、并发最后一个名额、锁定仍占名额、删除释放名额、账号重名及空白/超长输入。
- 修改姓名和重置密码成功/失败，旧密码失效；锁定/删除立即拒绝旧会话，解锁不复活旧会话。
- 子账号看不到账号管理，直接访问页面/API 被拒；主账号无法操作其他主账号的子账号。
- 共享数据可用、跨 owner 数据不可读写；Web 缓存不泄漏上一个账号的数据；其他全部功能有登录与操作冒烟覆盖。
- 原版/v2 子账号创建报告、编辑评价成功；创建学期/学科、配置课堂表现及间接写入失败；已有报告评价和分享仍兼容。
- 报告历史记录实际操作者，改名/删除后快照不变，Worker 显示系统事件，旧事件不伪造身份；并发编辑冲突不丢输入。
- 主账号和 Admin 日期范围、时区、聚合/去重/版本未知口径一致；子账号创建不混入注册统计，业务数据不重复计数。
- 接口/数据库失败、统计为空、权限拒绝、弹窗键盘关闭与手机布局。

开发交付必须执行全量 ESLint 与 `pnpm verify`，记录真实浏览器主子账号与 Admin 验收。PDF/OCR 如有改动，还需补脱敏样本并运行已有格式回归，不以数量替代内容核对。

## 8. 迁移、部署与回退

- 使用增量迁移添加账号关系/状态、事件操作者与统计归属/版本字段及索引；同步初始化 schema。已有账号默认 active 主账号，现有业务 teacher_id 不改写。
- 先迁移数据库，再同步发布 Backend、Worker、Web、Admin；不能在仍有旧 Backend 实例绕过状态/权限检查时开放子账号创建。多实例发布期间暂停新增子账号或在全部服务完成升级后启用入口。
- 迁移在保留既有账号、学科、学生、报告、分享和统计的测试库验证；禁止删库重建。迁移按字段、索引检测保持幂等；账号关系由服务端归属校验和事务锁维护，软删除不触发业务记录级联删除。
- 回退时保留新增列和审计数据，先关闭子账号入口并撤销子账号会话。已启用子账号后不能直接回退到不了解主子关系的旧认证服务，否则可能绕过锁定或访问错误的数据范围；需保留兼容认证/权限层或安排维护窗口。
