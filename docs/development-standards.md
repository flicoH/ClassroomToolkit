# ClassroomToolkit 开发与验收规范

本规范适用于 `apps/backend`、`apps/web`、`apps/admin` 和部署脚本。新功能以当前实际实现为基线；设计文档、代码、测试和部署说明应在同一变更中保持一致。

## 设计记录

新增或调整功能时，在相应 `docs/` 文档中写明：用户入口与完整流程、前后端接口和数据结构、权限和数据隔离、错误与重试方式、移动端行为、部署/迁移影响。涉及报告、积分或 PDF 等有业务口径的数据，写出来源、计算/选择规则及不能推断的内容。技术方案改变时更新文档，不保留与代码冲突的旧承诺。

## 弹窗与反馈

- 所有面向用户的确认、输入和提示使用项目内组件；禁止 `alert()`、`confirm()`、`prompt()` 及 `window`、`globalThis`、`self` 上的对应方法。Web 的危险操作优先复用 `components/ui/confirm-dialog.tsx`。普通结果用页面内状态、通知或表单错误呈现。
- 对话框应有清晰标题、说明、取消与确定/关闭按钮；支持 Escape、关闭后恢复焦点，提交时防止重复操作；窄屏不溢出，长内容可滚动。不可用遮罩点击作为唯一关闭方式。保留 `role="dialog"`、`aria-modal` 和可读标题。
- Admin 的 Vue 页面同样使用应用内组件，不通过浏览器原生弹窗绕过交互。新增通用弹窗时写交互测试；改现有弹窗时验证打开、取消、确定、Escape 和错误状态。
- `pnpm test:standards` 使用源码语法检查防止重新引入原生弹窗；扫描范围包括 Web、Admin 的脚本与 Vue 事件表达式。

## 注释与代码

注释解释业务约束、非显然算法、兼容理由、权限/安全边界和外部服务约定。公开函数或跨模块数据结构说明输入输出与关键限制；简单赋值和显而易见的 UI 文案不写重复注释。改动实现后同步检查注释，避免过期注释误导维护者。

## 测试验收

每个功能和缺陷修复都要有对应测试用例。至少覆盖：正常路径、输入边界、失败或无权限路径，以及修复前会失败的真实触发条件。后台业务规则用 Jest；Admin 交互用 Vitest；Web 交互用 Vitest；跨服务的关键链路补接口或端到端验证。测试使用脱敏样本，不能依赖个人数据库或生产服务才能运行。PDF 识别还需遵守 [课程 PDF 识别基准](semester-reports-setup.md#课程-pdf-识别基准)。

所有新增或修改的 JavaScript、TypeScript、Vue 代码（包括应用源码、测试、部署脚本与配置）必须经过 ESLint 检测，不能只依赖构建或暂存文件检查。`pnpm lint:eslint` 使用根配置全量只读检查；`pnpm verify` 首先运行 ESLint，再运行项目规范检查、三个应用现有测试，以及三个应用构建。自动测试不能证明真实浏览器、OCR 或外部服务完全正确；涉及这些环节时，还需记录使用的样本、环境和手工验收结果，不能把构建成功写成业务验收。若某项验证受环境限制，应明确记录未验证范围和原因。

新增可复用组件或公共逻辑时先补测试，再在根验证命令中接入。测试不能只镜像实现；应断言用户可观察结果或业务不变量。发现缺陷时把案例留在套件中，防止以后回退。

## 本地开发与验证构建隔离

Backend 的 `pnpm dev` 和调试热更新使用 `tsconfig.dev.json`，输出及增量缓存位于 `.dev-dist/`；生产构建、迁移命令和容器入口仍使用 `dist/`。生产编译排除 `.dev-dist/`，避免编译开发生成的声明文件。不得让 watch 与 `pnpm verify` 共用可被清空的输出目录，否则验证构建可能使热更新重启失败，Web 代理表现为学期、学科、积分、报告和埋点接口统一「后端服务连接失败」500。已有旧 watch 进程需重启一次以读取新的配置；运行验证后检查根路径公开健康接口及应用接口连接，不能仅用构建成功代替运行态验收。该调整不更改业务 API、认证、数据库或部署产物路径；无需迁移。`check-dev-build-isolation.test.mjs` 校验有效 TypeScript 输出目录、增量缓存、开发声明文件排除与生产启动路径，纳入 `pnpm verify`。

2026-10-10 运行态回归：旧 Nest watch 进程仍在但无 HTTP 子进程，3000 端口连接失败；临时启动当前产物后恢复。已切换到独立 `.dev-dist` 的热更新服务，并在它运行时执行完整 `pnpm verify`（Backend 283、Web 59、Admin 11 项及三端构建全部通过）。生产构建后公开根路径返回 HTTP 200；使用当前 Chrome 的登录会话重新打开学期报告 v2，网络面板确认学期、学科、积分、报告列表、课程资料均为 200，埋点为 201，页面加载出已有学期、11 名学生和报告。未重建数据库或改写既有报告。


## ESLint 检查入口与覆盖（2026-10-11）

根命令 `pnpm lint:eslint` 执行 `eslint .`，覆盖 Web、Backend、Admin 源码和测试，以及 JS/TS/JSX/TSX/Vue/MJS/CJS 脚本、配置；交付与 CI 通过 `pnpm verify` 首先执行该命令，错误会停止后续验证。提交前 lint-staged 保留自动格式化及 `eslint --fix`，增加 MJS/CJS 匹配。后续开发必须执行检查并修复所有错误，现有 warning 沿用原规则且不作为阻断；不得为通过检查扩大源码忽略范围或关闭不兼容以外的规则。

根配置使用全局 ignores 只排除依赖、Git 元数据、构建/覆盖率产物和 Next 自动声明文件，源码测试与 scripts 目录参与检查；Vue 单扩展名匹配采用 `**/*.vue` 并正确解析 TypeScript，Backend 单扩展名采用 `**/*.ts`。CJS 保留 CommonJS 语法，仅对该扩展名允许 require，其他检查继续生效。Python/Shell 等非 ESLint 支持的代码继续使用原验证工具。API、权限、数据库和部署服务行为不变，无迁移。

`check-eslint.test.mjs` 防止验证入口、提交扩展名覆盖、源码/测试/脚本检测、生成目录排除及 Vue TypeScript 解析退化；集成到规范测试。

验收：包含全量 ESLint 的 `pnpm verify` 完整通过，规范测试 23 项、Backend 321、Web 87、Admin 11 项和三端构建通过。全量 ESLint 为 0 错误；历史 warning 保留，主要为新增覆盖的 Vue 模板格式及既有未使用变量提示。没有批量重写既有业务文件。

### v2 按学科保存课堂表现（2026-10-12）

- v2 生成表单和草稿为每门已选学科分别提供课堂表现输入，英语使用“英语开口”，其他学科使用“学科表达”。同一项目可在不同学科保存不同评价，清空只影响当前学科。报告预览、家长页与图片导出共用分学科展示；每门学科始终有课堂表现区域，未填写时显示“老师暂未填写具体课堂表现”，不根据积分推断评价。
- 现有生成接口的 `studentFeedback[].classroomPerformance[]` 增加可选 `subjectId`，保留 `label/value`；草稿正文的 `classroomPerformance[]` 增加可选 `subjectId`，保留 `text/sourceRefs`。后台在批量生成前验证学科属于已选范围；保存草稿时验证学科属于该报告，每科最多 12 项，同科项目不能重复，v2 总计最多 240 项。非法学科、空白评价、无效引用、超过限制均按现有接口返回 400；报告编辑、学科调整和历史恢复沿用教师归属校验及事务锁。
- 学科名称和 ID 在生成快照中保存为 `reportSubjects: [{subjectId, name}]`，正文/对外展示由服务端快照覆盖该字段，客户端不能改变报告学科。增加学科提供空白评价区，删除学科同步删除其正文和生成输入里的评价，并保留其他学科及未保存编辑。流程详情以中文学科名称标明课堂表现变化，恢复历史版本会一起恢复当时的学科与各科评价。
- 旧 v2 报告优先根据快照 `courseSelections`（缺失时根据课程资料的 `subjectId`）提供学科区域；旧未标注学科的评价保留在“未分学科的原课堂表现”独立区域，不复制到每门学科。编辑其他学科时保留旧自由文本和原引用，修改的评价标记教师核对引用。原版报告保留共用课堂表现。
- 使用现有 JSON 字段，无数据库迁移、不重建数据。部署需要同步更新 Backend 与 Web；已有分享链接继续使用共用报告视图显示各科评价。
- 回归覆盖两学科同项目不同评价、每科独立清空/表达分类、跨学科或超限输入、旧报告与自由文本保留、草稿添加/删除成功及失败、保存和历史恢复、预览/导出分学科展示。交付前执行全量 ESLint 和 `pnpm verify`。

- 验收：`pnpm verify` 通过（ESLint 0 错误；Backend 324、Web 90、Admin 11 项测试及三端构建通过），Web `tsc --noEmit` 通过；同时修正两份既有 Web 测试里的数组索引类型断言，未改变测试行为。
