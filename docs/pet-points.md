# 宠物积分养成与余额口径

当前实现见 [分支规格](../sdd/featuer/pet-points-refinement/spec.md)与[技术设计](../sdd/featuer/pet-points-refinement/design.md)。本修订需要新增迁移；旧版“score决定等级、重置清空积分、能量决定完成数量”的口径已替换。

`score` 是可用课堂积分，评分加扣和奖品兑换会改变余额。`petExperience` 是当前养成轮次经验，评分加扣会改变经验，兑换不影响经验或等级。满级和重置不清空积分、徽章或完成档案。阈值由教师最大等级与finalEnergy生成：第i级阈值为 `floor((i-1)*finalEnergy/(maxLevel-1)+0.5)`，等级取经验达到的最高档。默认10级/200经验；10级/100经验对应0、11、22、33、44、56、67、78、89、100。前后端采用同一口径，下一等级阈值用于进度分母。

绑定宠物后正向评分首次跨级领取成长徽章，10级默认自动奖励预算为每轮最多50枚；中途调整规则也不超发；扣分降级不回收，重升和换宠不重复领取。中途换宠保留本轮经验、能量、余额和领取标记。`petProgress` 仍是独立正向成长能量，达到上限不自动完成；中途重置和正常完成将它清零。中途重置清除宠物及本轮经验，已达到奖励档位受到保护，不能通过重置刷徽章。

达到最终经验后保存待完成状态，教师确认“完成本轮”才归档。每轮满级宠物以独立快照进入养成成就，并在成长徽章区域关联满级纪念和本轮实际获奖记录；历史获奖与当前可用徽章余额分开展示。完成数只增加一次，旧宠物保留完成时的形态、昵称、日期与规则；下一轮经验结转超出上限部分，恰好满级则从0开始。可选择新的或同种宠物重新养成，取消/失败仍保留档案及待选状态。奖状从所选完成快照生成PNG预览与下载，合影展示完成纪念，不虚报文件保存。

评分、多个指标、学生更新、形态历史、升级奖励、归档和兑换各自在统一事务中提交。所有业务写请求使用operationId防重和学生revisions（设置使用expectedVersion）；不兼容旧客户端写请求返回409要求刷新。失败保留输入，响应不确定时复用原操作编号；保存成功但刷新失败只重试读取。记录保存请求值及实际余额/经验/能量变化；回退按实际量处理，跨轮仅回退余额，不修改新宠物或旧档案；缺少证据的旧记录限制回退。

搜索、分组和排序仅在前端筛选；班级同步由服务端读取规范完整名册，不相信客户端子集。移出名册的学生隐藏但保留原行与全部积分、兑换和成长历史。普通批量排除请假学生，高级评分允许明确包含并提示；请假标记和教师徽章调整真实持久化，没有每日自动过期。

迁移保留旧score/petProgress/trophies/completedPets与报告历史；新经验映射到旧等级的新阈值区间，保存迁移证据，已达等级仅标记处理、不补发徽章；无旧完成快照时不编造宠物档案。报告继续按截止时间的形态历史获取宠物，已发布报告不重写；评分汇总维持已有请求delta口径，本页新增实际记录净值统计并标明缺失证据。部署必须先迁移并更新Backend，再更新Web；新轮次写入后不能回滚到把score当经验的旧后端。

原有四系15种宠物与全部清理素材保留，未修改PDF解析、OCR或历史报告内容。验收结果与尚未验证项见[任务清单](../sdd/featuer/pet-points-refinement/tasks.md)。

学生完整逻辑ID与存储主键分离，避免长学号在教师前缀拼接截断后覆盖他人进度。既有主键和报告引用保留，评分/兑换读接口映射回完整逻辑身份。MySQL迁移可在部分DDL已提交后安全续跑，不重置已开始的新养成轮次。发布前需暂停旧Backend写入；仅兼容经验/轮次的新UI允许回滚，不能回到以余额推导等级的旧UI。
