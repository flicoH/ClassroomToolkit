# 学期报告配置与使用

当前分支已实现教师端资料/报告流程和家长公开页面。上传 PDF 默认使用 Kimi 云端文件解析；如需原 Docling 服务，必须显式设置提供方为 `docling`；报告可使用无需 AI 的本地模板生成，也可切换到 Chat Completions 兼容文本模型。分享仍需设置公开站点地址和链接加密密钥。生产密钥放在服务端 `deploy/.env.backend` 或 2C2G 配置 `deploy/.env.2c2g`，不要提交仓库或传给浏览器。

## 移动端学期报告工作区

教师从首页打开「学期报告」。小于 768px 时，页面提供固定在滚动区域顶部的「课程资料 / 填写报告 / 报告列表」导航，每次只显示一个区域；切换会回到区域顶部，已选学生、授课范围、逐人反馈、报告基础信息及章节修订保留在同一组件状态中。切换区域不重新发起列表请求，不把未提交内容自动保存到服务器；关闭工具或刷新页面仍会丢失未提交表单。768px 及以上仍同时展示资料、填写区与报告列表。

当前学期与学科显示在导航下方，填写/列表区可通过「更换」回到资料区。已有学期与学科时收起新建表单，首次使用缺少任一配置时自动展开；原有创建、上传、核对和生成条件继续生效。上传入口支持键盘焦点，文件卡片分开呈现文件名、状态、错误和操作。手机触控按钮至少 44px，输入字号至少 16px；长文件名/错误换行，不压缩重试与删除按钮。PDF 重试失败通过页面状态展示，不留下未捕获的请求错误。

提交生成成功后切到报告列表，失败时留在填写区并展示错误；草稿预览仍为带关闭入口的全屏移动端弹窗，Escape 可关闭，关闭后恢复触发按钮焦点。学习目标的掌握选择在手机上占一整行，反馈内容随页面滚动，避免内层目标列表抢占手机滚动。所有 API、请求字段、权限、数据隔离、PDF 解析流程及数据库结构保持原有契约，本次不需要迁移或新增环境变量。

回归用例位于 `apps/web/components/apps/SemesterReports.spec.tsx`，覆盖区域切换保留输入/学生/反馈、首次设置边界、失败重试和生成后导航。2026-10-09 使用独立本地预览和脱敏样本检查手机尺寸；不使用真实学生数据或发布家长链接。真实 iOS/Android 键盘与安全区仍需设备复测。

## Kimi 云端 PDF 解析（默认）

本地测试在 `apps/backend/.env` 配置；生产在 `deploy/.env.2c2g`（小内存部署）或 `deploy/.env.backend` 配置：

```dotenv
KIMI_API_KEY=在环境文件中填入已注册的真实密钥
KIMI_BASE_URL=https://api.moonshot.cn/v1
SEMESTER_REPORT_PARSER_PROVIDER=kimi
```

提供方留空时也默认 Kimi，教师上传后自动进入解析队列，不需要选择解析方式。配置后重启本地后端，生产重新创建容器；单纯 restart 不会更新 Compose 环境。密钥只放服务端，不提交 Git、不发到聊天或放入前端变量。**无需 Poppler、pdfinfo、pdftoppm、Docling 或本地 OCR 模型。**旧的 `KIMI_MODEL` 配置对 PDF 文件解析不再生效：这条链路使用 Kimi 官方文件提取服务，不调用 Chat Completions。

解析流程：上传 → 原件保存在私有卷 → `pdf-lib` 读取页树并复制单页 PDF → 逐页 POST `/v1/files`，`purpose=file-extract` → GET `/v1/files/:id/content` 获取云端提取的 Markdown → DELETE `/v1/files/:id` 删除临时云端文件 → 保存对应原页码的文本 → 原有课时提取 → 教师核对。接口遵循 [Kimi 文件上传](https://platform.kimi.com/docs/api/files-upload) 和 [文件内容](https://platform.kimi.com/docs/api/files-content) 文档；文件请求使用不携带测试版版本头的标准兼容接口，接受纯 Markdown 或 JSON `{content}` 包装；本地已确认当前密钥在带 beta 版本头时被拒绝，标准接口可用。

本机只复制 PDF 页对象，不识别文字、不渲染图片、不加载模型。逐页上传是为了保留原始页码：云端整本 Markdown 不保证保留分页，不能让模型猜页码。每次仅保留当前单页上传数据，完成后再处理下一页。`sourcePages`、课时候选、教师确认及 `course:<文档ID>:p<原页码>` 引用沿用现有数据结构，无需前端接口或数据库迁移。页面尺寸、旋转、文字/图片资源由单页复制保留。

30MB、300 页、每页 50,000 字、全文 1,000,000 字限制保留；整个任务限时 10 分钟，单次云请求 90 秒，清理请求最多 15 秒。300 页是上限，不保证在限时内完成，复杂或长文档请拆分上传。加密或损坏 PDF 在上传云端前拒绝；空白页保留，整份空文档拒绝；缺页、重复页、响应超限或失败不能保存为待确认的部分结果。后端本地任务上限低于 15 分钟队列回收窗口。

密钥只在后端使用，单页 PDF 会发到配置的 Kimi API，以通用名 `course-page.pdf` 上传，不附加原文件名、学生记录、积分或教师观察。PDF 自身包含的信息仍会发送。云端成功取得文本或失败后都执行临时文件删除；删除失败会明确报错并要求到 Kimi 控制台清理，不声称清理成功。云端上传已成功但响应中途丢失、未取得 file ID 时，无法自动定位并删除该文件，需到控制台核对。

401/403 检查密钥与权限，429 检查限额或稍后重试，5xx/连接失败稍后重试。文档失败后由教师点击「重试」，不自动重传或切换 Docling。成功页不单独缓存，重试会重新处理整份文档；文件提取价格、配额与限流以 Kimi 控制台为准。报告生成与解析独立：2C2G 仍用 `template`，不设置 `REPORT_AI_*` 即可生成报告。默认解析器的改变不会重解析既有成功文档或自动重试失败任务。

## Docling 解析服务

`SEMESTER_REPORT_PARSER_PROVIDER=docling` 时可使用 Docling；`deploy/compose.backend.yml` 的解析容器归入 `docling` profile，需通过 `--profile docling` 显式启用，后端通过 `http://docling-parser:8000/parse` 调用。解析在自有服务器本地完成，服务只在内部 Docker 网络监听，不暴露公网端口。容器启用 Docling OCR、RapidOCR 简体中文模型和表格结构识别；模型在镜像构建时下载到 `/opt/docling-models`，运行时不依赖联网下载或缓存卷。解析器限制为 1.5GB 内存、1 个 CPU 核，并将 OCR、版面和表格批次降至 1；这会降低并发/速度，不消除服务器资源不足的风险。Docling 代码和 OCR 模型许可证需分别遵守其上游条款。

### 本地开发

在仓库根目录启动开发用解析服务：

```bash
docker compose -f deploy/compose.docling.local.yml up -d --build --wait
```

设置 `apps/backend/.env` 中的 `SEMESTER_REPORT_PARSER_PROVIDER=docling` 和 `SEMESTER_REPORT_PARSER_URL=http://127.0.0.1:18000/parse`，再启动或重启后端。开发容器只绑定本机 `18000` 端口，并持续运行；容器内部的 `docling-parser` 域名只适用于同一 Docker 网络内的后端，本机运行的 Node 后端必须用上述本机地址。可用 `curl http://127.0.0.1:18000/health` 检查服务。修改配置不会自动重试历史失败任务，需在教师端点击「重试」。停止解析服务使用 `docker compose -f deploy/compose.docling.local.yml down`。

解析接口收到 `multipart/form-data` 中名为 `file` 的 PDF 后，返回 JSON：

```json
{
  "pages": [
    { "page": 1, "text": "第一页识别出的文本" },
    { "page": 2, "text": "第二页识别出的文本" }
  ],
  "units": ["第一单元 有趣的图形"]
}
```

`page` 是从 1 开始的原 PDF 页码。每一页都要返回，包括扫描页 OCR 结果；页面缺失、页码异常、单页超过 50,000 字或全文超过 1,000,000 字会被拒绝。章节 `units` 只用于教师核对，报告引用以实际页码为准。需要更换解析器时，将 `SEMESTER_REPORT_PARSER_URL` 指向实现同一接口的适配器；服务访问凭证可配置在 `SEMESTER_REPORT_PARSER_API_KEY`，该值会同时传给解析容器和后端。

### 课程 PDF 识别基准

更换 Docling 配置、OCR、PDF 服务或后端章节提取逻辑时，按以下规则验收；以**实际课程表的课时行和原 PDF 页码**为准，不能只看解析服务返回的 `units` 数量。

| 样本格式                          | 必须识别的内容                                                                                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Unit`／`Lesson` 表格或标题       | 区分 `Unit1` 与 `Unit10`，列出单元内课时；`Unit1 1` 能定位第 1 单元第 1 课及其跨页续文。                                                                                |
| `课时｜课程｜目标及内容` 编号表格 | 把 `01`、`02` 等行识别为课时；同一 PDF 不同册的同号课时分别保留。没有目标单元格的复习、测评行仍是课时。                                                                 |
| `周/课次｜单元名称` 表格          | 将表格序号与 `第 N 课《标题》`、`复习课`对应；现有硬笔书法样本应为第 1～18 课，含第 9、18 课复习。                                                                      |
| 拼音王国样本                      | 应列出第 1～81 课，包括末尾第 80 课“大复习”和第 81 课“阶段测评四”；“第 37 周进行阶段重点内容评估”等叙述不是章节。                                                       |
| 与上述版式相近的新课件            | 容忍全角表格线、表头空格和近义词（如“教学主题”“课题名称”“课时编号”）、前置周次列、跨页无重复表头，以及明确写有“第 N 课”的行；不要求文件名、课时总数或每列文字完全相同。 |
| 没有可靠章节的扫描件或普通文本    | 保留每页 OCR 文本和真实页码，允许按“第 N 页”选择，由教师核对。                                                                                                          |

后端从按页文本识别到具体课时时，以该结构化结果为候选，不让 PDF 服务返回的少量标题覆盖整张课程表。仅在后端只能提供页码时使用解析服务的章节候选；两者都没有章节时按页选择。候选不是自动确认：老师可以修改、确认；新版识别到更多课时的旧课件可点「重新核对章节」，无需重新上传。选择某课时后，报告只引用该课时及续页的教学内容，不把同页其他课时混入；无法匹配时提示核对范围，不用整本 PDF 冒充命中。

识别逻辑的回归测试在 `apps/backend/src/semester-reports/course-scope.spec.ts`，运行 `pnpm --filter ClassRoomToolkitBackend exec jest src/semester-reports/course-scope.spec.ts --runInBand --no-watchman`。接入新的 PDF 版式时，增加脱敏的真实表格片段和预期课时、页码、学习内容，再改解析规则。

### 无需 AI 的报告生成

教师端默认选择「本地模板（无需 AI）」。模板按当前周期的实际评价项目整理加分与扣分，列出老师确认的授课范围、课程资料页码及教师观察，生成可编辑草稿。关键词作为教师关注主题，不作为学习成果；没有评价或观察时明确说明资料不足，不推断知识掌握程度。生成方式会显示在教师列表、家长页面及流程记录中。已有因未配置 AI 而失败的任务可以点击「重试」，在全部 AI 配置为空时自动使用模板；仍需由老师审核后发布。

选择学生和报告起止日期后，教师页面通过登录接口 `POST /semester-reports/reports/preview-input` 按学生展示该周期的宠物积分加分、扣分、净积分和明细；仅使用当前教师对应学生的评价记录。结束日期包含当天，数据库查询使用上海时区的 `[开始当天 00:00, 结束次日 00:00)`。生成时重新查询并冻结积分快照，报告与免登录家长页展示同一份快照，后续积分变化不会改写已生成报告；重新生成会取新快照。每份报告总数和合计覆盖周期内全部记录，明细最多展示前 80 条，超出时明确标注。兑换不属于课堂评价加减分，学科报告中的积分仍是综合积分。积分明细由后端快照确定，草稿编辑不能篡改数值；家长接口不暴露学生内部 ID、评价记录 ID 或备注。

报告内部快照只在后端用于生成、校验和追溯。教师的报告摘要、详情及发布响应均不返回原始快照，公开家长接口也只返回展示所需的白名单字段。

教师预览和家长报告的区块标题统一为「本期积分加减情况」。点击「加分」或「扣分」汇总卡片只筛选当前可见明细，点击「净积分」恢复全部；汇总数字保持完整周期口径，不随筛选变化。超过 80 条时筛选仅覆盖已展示的前 80 条，不声称筛出了全周期所有同类记录。

`REPORT_GENERATION_MODE` 支持 `auto`、`template`、`ai`，用于没有指定生成方式的请求和旧任务。默认 `auto` 在三项 AI 配置均为空时使用模板，三项齐全时使用 AI；部分配置缺失会提示补齐或选择模板。明确选择 AI 的任务不会在 API 故障时自动改为模板。

选择 AI 生成时，`REPORT_AI_BASE_URL`、`REPORT_AI_API_KEY`、`REPORT_AI_MODEL` 配置兼容 `/chat/completions` 与 JSON object response format 的文本模型。例如 base URL 应为服务提供的 API 根地址，不附加 `/chat/completions`。模型需遵守输出 schema，并在每条亮点、改进建议和家庭建议上引用系统传入的原始页码或评价 ID；引用无法通过校验的草稿会失败，教师不能发布无依据的正文。

链接加密密钥生成示例：

```bash
openssl rand -base64 32
```

设置 `REPORT_SHARE_ENCRYPTION_KEY`。密钥与数据库备份分开保存并纳入密钥轮换/灾备流程；更换密钥前，先迁移仍需复制的活跃链接密文，否则教师无法从历史报告列表重新取回链接。`REPORT_PUBLIC_BASE_URL` 设置家长访问的 HTTPS 网站根地址。

## 教师流程

1. 在桌面打开「学期报告」，建立学期和学科，选择一份 PDF 上传。
2. 等待文档队列状态从「排队中/解析中」变为「待确认」；核对自动提取章节，删改章节后点击确认。解析失败时可以重试。解析结果没有可辨认的单元或课时标题时，页面会列出原 PDF 页码供核对和选择，不需要重传文件。已确认的旧课件如果新版识别出更多章节，点击「重新核对章节」即可用新版候选更新，仍需老师确认，不必重新上传。
3. 选学期、学科、周/月/学期周期、学生和关键词。周报/月报可点击课程名称填写授课范围；`Unit1 1`、`Unit1 第1课`、`第一单元 第一课` 均代表第 1 单元第 1 课；`Unit1 1-3` 表示第 1 至 3 课。普通 Markdown 标题及表格内的编号课时也会成为可选范围，同编号的不同教材册次分开选择。对于没有章节结构的 PDF，可选「第3页」或输入「第3-5页」；多个范围用顿号分隔。再次点击可取消选择。页面列出所选学习内容与原 PDF 页码；直接选择页码时显示该页提取的文本，老师应核对命中页。学期报告覆盖所有已确认资料。学生支持按班级筛选、搜索姓名、批量选择筛选结果及单独移除；一次最多选择 30 人，跨班级选择会保留，每人生成单独任务。
4. 在生成页面填写报告抬头、课程主题、课次及周期内的授课日期。选择学生后，切换姓名可查看各自「本期积分加减情况」并点击加分、扣分筛选明细，分别填写逐项掌握评价、8 项课堂表现、老师寄语、值得肯定的表现、下一步重点和家庭练习。所填文字与评价直接带入对应学生的草稿。
5. 查看生成状态。生成后仍可在草稿中编辑评价与文字；解析服务不可用、超时或引用校验失败可重试。列表仅加载报告摘要，打开预览时再请求正文。手动新增条目标记教师核对来源。
6. 点击「查看报告模板」预览蓝紫色页首、学习内容与掌握、课堂表现标签、宠物积分加减明细、老师寄语、肯定/重点卡片和家庭练习。教师预览与家长页面复用同一模板。保存后发布，分享免登录链接；浏览器拒绝复制时，仍可在链接框手动复制。删除报告会撤销链接。
7. 已发布报告需要修改时，点击「撤销链接并编辑」：所有现有家长链接立即失效，报告回到「待审核」并自动打开草稿编辑窗口。正文、课程证据和积分快照保留；编辑不会重新计算原周期积分。保存并重新发布后生成新链接，旧链接继续失效。历史报告已撤销或已过期、列表没有有效链接时，点击「重新编辑」也可回到草稿。

## 撤销分享后重新编辑

- `DELETE /semester-reports/reports/:id/shares/:shareId` 返回 `{ revoked: true, status }`。首次撤销有效链接会将 `published` 改为 `draft`，清空 `publishedAt`，撤销此报告全部未撤销链接并清空其加密令牌；保留正文和内部快照。已经撤销的旧链接重复请求不改变新的发布状态，响应带回报告实际状态。
- `POST /semester-reports/reports/:id/unpublish` 返回 `{ status: "draft" }`，用于历史已发布报告没有有效链接时的重新编辑。草稿重复调用保持草稿；排队、生成中、失败报告拒绝请求，已删除报告不可访问。
- 两个接口均要求教师登录，同时校验报告归属；指定分享链接还需校验链接与报告及教师的归属。撤销与状态变更、事件记录在同一数据库事务提交；发布、创建链接、撤销及保存草稿通过报告行锁串行处理。保存失败时事务回滚，保留原来的链接与发布状态。撤销产生 `share-revoked`、`report-unpublished` 流程事件，重新发布仍需通过正文引用校验。
- Web 使用同源 `/api/semester-reports/...` 路径。手机和桌面均在撤销成功后打开现有编辑弹窗；撤销失败显示页面错误，不解锁正文。撤销后强制读取最新列表、详情及流程，避免刚查看的已发布内容被短时请求去重缓存复用。正文加载失败时草稿仍保留在列表，可再次点击「预览 / 编辑」。旧撤销请求返回已发布状态时不会强行打开编辑。
- 不新增环境变量或数据库迁移；上线需同步更新 Web 和 Backend，以支持新状态响应和重新编辑接口。后端回归覆盖旧链接失效、重新发布新链接、内容与快照保留、重复撤销、历史状态、归属校验和事务失败；前端回归覆盖自动编辑、保存修改、历史报告入口、权限失败、短时缓存与正文加载失败。自动测试使用脱敏数据与仓库 mock，真实 MySQL 并发和设备访问仍需上线验收。
- 2026-10-09 在独立脱敏预览、375×812 浏览器视口中核对：撤销后显示待审核并自动打开编辑窗口；修改寄语、保存、重新打开后保留新文字，Escape 关闭并恢复「预览 / 编辑」按钮焦点。此次浏览器验证使用本地请求替身，不访问真实学生记录或创建公开链接。完整 `pnpm verify` 通过（后端 214、Web 19、Admin 8 个测试及三个应用构建）。

## 当前约束

- 上传上限 30MB、每份 PDF 最多 300 页；生成单次最多 30 名学生和 20 份课程 PDF，送入模型的课程文本最多 120,000 字，逐项学习内容最多 500 项。超过上限时提示拆分文件或缩小范围，不截断后继续生成。
- 周/月报告由老师提交本周期章节文字作为授课范围；目前未实现按班级维护可复用的日期到章节进度表。
- Docling 与 Kimi 解析已接入；扫描件、表格、目录及页码映射质量需用实际课程样本核对。Docling 镜像首次构建需联网下载模型文件；Kimi 后端无需下载 OCR 模型。
- worker 与后端服务同进程轮询 MySQL，适合当前低并发部署；尚无独立扩缩容、全局用量计费面板或自动过期清理策略。
- 原 PDF 与解析文本在教师删除文档时清理；已生成报告保留自己的证据快照，需在报告列表单独删除。报告删除会撤销链接并清空报告正文/快照，但保留最小事件记录。

解析代码已接入，但仅构建成功不等于真实课程 PDF 的 OCR 质量或 AI 报告事实质量已验收。
