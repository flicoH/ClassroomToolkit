## 合并 main 的冲突解决（2026-10-16）

将 `featuer/semester-reports-v2` 合并到 `main` 时，报告视图及两份回归测试发生冲突。不能只删除标记后同时保留两端区块，否则课堂表现与旧未分学科评价会重复出现。

- 沿用 main 的学生头像、标题下方课堂照片与说明、成长总结之前的课堂表现布局；分支中的评价可见性规则合入这一处区块，不保留旧位置的第二套展示。
- 合并 main 原有照片/头像/原版兼容测试与分支的四科家长页、无照片评价、空白评价及去重断言。保留旧未分学科评价独立小节，不复制给其他学科。
- 无 API、数据结构、权限或数据库迁移变化；家长链接有效性和错误处理保持原样。部署 Web 后原报告即可显示保存的评价，无需重新生成。
- 验证：先在 main 原实现上确认 4 项评价回归失败，修复后相关 40 项通过；完整 `pnpm verify` 通过（ESLint 0 错误，Backend 397、Web 203、Admin 11 项及三端构建通过）。本机开发服务的报告路由返回 HTTP 200，渲染报告加载页，无冲突语法报错。Git 冲突已解决并暂存，未创建合并提交或部署线上。

## 线上缺陷修正（2026-10-16）

分支适配：`featuer/semester-reports-v2` 恢复暂存修复时与本分支较早的布局产生冲突。合并时沿用本分支的标题区课堂照片及成长总结之后的学科区块，保留周期文案与独立的旧未分学科评价，只合入评价可见性规则；不引入其他分支的学生头像或照片位置功能。对应测试增加区块不重复的断言，避免只删除冲突标记后重复展示。下文原验收数量属于首次修复所在分支。当前分支验证：针对只删除冲突标记后的重复区块及空区块，4 项回归先失败；正确合并后相关 33 项通过，完整 `pnpm verify` 通过（ESLint 0 错误，Backend 364、Web 148、Admin 11 项及三端构建通过）。本机开发服务报告路由返回 HTTP 200 并渲染加载页面，未再出现冲突语法错误；Git 未合并状态已清除，未创建提交或部署线上。

本节替代下文此前“无课堂照片时隐藏整个课堂表现区块”的显示规则。线上报告已保存学科和课堂评价，但共用视图因两个照片位置均为空而隐藏全部评价，导致教师流程记录与家长报告不一致。

- v2 课堂表现区块在任一课堂照片存在，或任一已保存评价文本去除空白后非空时显示；照片与头像独立按现有规则展示。没有照片且没有有效评价时仍隐藏空区块。
- 按 `reportSubjects` 顺序展示各学科及对应 `classroomPerformance`，未填写学科保留原提示；旧未分学科评价保留独立小节，不复制到其他学科。

- 仅更新 Web 展示，无 API、数据结构、权限、后端失败行为或数据库迁移变化；失效或撤销链接继续显示原错误，不展示报告。上线需部署包含修复的 Web 产物，刷新原链接生效。

## 需求与展示顺序

1. 老师可以在学生管理中上传学生照片，学生列表优先展示照片；没有上传时使用现有姓名首字与图标。
2. v2 报告的蓝紫色标题区域右侧展示该学生的圆形头像，对应需求图 1 标注位置。
3. v2 报告的课堂表现移到标题区域下方、学习习惯与能力成长总结上方，对应需求图 2 标注位置，区块标题为“课堂表现”；有课堂照片或已填写课堂评价时显示，两者都没有时隐藏空区块。

调整后的 v2 报告顶部顺序：

```text
蓝紫色标题区：左侧报告信息，右侧圆形学生头像
白色课堂照片区：照片及说明，无照片时省略
课堂表现：有课堂照片或已填写评价时按学科展示，两者都没有时省略空区块
本学期学习习惯与能力成长总结
后续现有报告区块
```

课堂表现区块根据内容自然增高，截图红框表示插入位置，不作为固定高度。学生头像与现有课堂照片为独立数据，分别保留展示用途。

## 学生照片流程

### 教师入口

- 在学生编辑弹窗增加当前照片预览、“上传/更换照片”和“移除照片”。新学生先保存资料，再上传照片，避免创建失败后产生无归属照片。
- 文件选择入口使用带上传图标的蓝色“上传照片/更换照片”按钮；窄屏整行显示，点击高度至少 44 像素，支持键盘激活。选择图片后显示保存步骤提示、预览与上传状态，上传成功更新对应学生卡片；失败显示表单内错误并支持重试。
- 允许 JPG、PNG，原始文件最大 2MB。建议上传前将图片按比例缩小至最长边 512 像素并转换为 JPEG，上传产物最大 256KB，控制班级列表与报告快照体积。透明部分使用白色背景，具体处理规则实现时同步写入文档与测试。
- 上传过程中禁用重复提交；移除使用项目内确认弹窗，成功后恢复现有姓名首字展示。
- 照片通过 `object-fit: cover` 在圆形容器内居中展示，保留原始宽高比例，不拉伸图片。首期不增加裁剪编辑器。
- 学生列表加载照片失败时回退到现有头像样式，不影响姓名、学号和分组操作。
- 弹窗提供可见关闭入口、Escape 关闭、焦点恢复及窄屏滚动布局，使用页面内状态反馈。

### 数据与接口

拟新增学生字段：`photo: string | null`，保存经过限制的图片 Data URL；数据库新增可空的 `photo` 文本列，具体容量按上传产物限制选取。采用数据库迁移，已有学生默认值为 `null`。

复用现有图片随数据保存的方式，无需新增对象存储或公开文件目录。照片字段只能通过专用上传/删除接口修改，普通资料编辑不能注入外部图片 URL 或覆盖照片。

| 接口                                                     | 用途                          | 返回                                |
| -------------------------------------------------------- | ----------------------------- | ----------------------------------- |
| `POST /classes/:classroomId/students/:studentId/photo`   | multipart 上传，字段为 `file` | 更新后的学生资料                    |
| `DELETE /classes/:classroomId/students/:studentId/photo` | 移除照片，可重复执行          | 更新后的学生资料，`photo` 为 `null` |
| 现有班级与学生查询接口                                   | 展示学生照片                  | 学生结构增加可空的 `photo`          |

Web 沿用现有 `/api` 代理访问这些接口。服务端校验上传大小、实际文件类型、图片可解码性与尺寸，拒绝 SVG、伪造 MIME 和损坏文件。前端处理不替代服务端验证。

照片更新应按当前教师、班级和学生条件执行，避免通过保存整个班级覆盖并发修改。其他学生资料保存流程需要完整保留照片字段。

### 权限与失败行为

- 沿用当前教师身份与数据隔离；只能修改教师自己班级中的学生照片。
- 学生或班级不存在、属于其他教师时沿用现有不可见资源的响应规则，不泄露照片。
- 非法图片返回清晰的校验错误；超过上传限制沿用框架的请求大小错误并转换为用户可读提示。
- 上传或删除失败保留原照片，客户端不得先将成功状态写入列表。
- 照片不发送给报告 AI，不作为评价、成绩或课堂表现的推断依据。

## v2 报告头像

- 首次生成 v2 报告时，读取对应学生已保存的照片并写入报告快照，同时通过报告内容接口提供给共用视图。
- 草稿普通编辑不能修改照片快照；重新生成与历史恢复保留对应版本的照片，避免修改学生照片时已发布报告发生隐式变化。
- 没有照片的报告快照明确记录空值。旧报告缺少照片字段时按无照片处理，需要新生成报告才携带学生照片。
- 报告蓝紫色标题区域右侧显示圆形头像，桌面建议直径 128 像素，窄屏建议 72 像素；使用白色边框，与左侧报告标题留出间距。
- 长学生姓名和窄屏布局允许文本换行，头像不被压缩或挤出容器；无照片时保留现有标题布局。
- 家长页仅通过现有有效分享链接读取该报告快照中的照片，不增加公开学生资料查询接口。
- 预览、家长分享页和图片导出使用相同展示逻辑；导出前等待头像加载完成，避免导出图片缺少头像。
- 报告列表等轻量查询继续避免读取图片正文；照片只在报告详情、分享与导出所需的数据中返回。

## v2 课堂表现布局

- 将当前 v2 的分学科课堂表现放在标题区下方的白色课堂照片区域之后，并放在成长总结之前，主标题固定为“课堂表现”。报告两个课堂照片位置都为空且没有非空课堂评价时，隐藏整个区块；任一位置有图或存在已填写评价时显示。旧单图字段继续兼容，学生头像不作为此显示条件。
- 继续使用 `reportSubjects` 与 `classroomPerformance` 数据，按报告学科顺序显示学科小标题及该学科评价，不改变教师录入与保存规则。
- 区块显示时，没填写的学科显示“老师暂未填写具体课堂表现。”，不根据积分或教学内容推断评价。
- 旧 v2 中未标注学科的评价放在该区块内的“未分学科的原课堂表现”小节，保留自由文本和引用，不复制到各学科。
- 移动后删除原位置的重复展示；不保留“本学期学习表现”或“课堂表现记录”作为重复的区块标题。
- 多学科在宽屏采用两列，窄屏单列；长评价自然换行，图片导出包含全部内容。
- 原版报告继续使用现有布局；此次位置调整适用于共用 v2 展示视图。
