# 学生照片与报告头像

学生照片用于学生管理列表和学期报告 v2 的身份展示。实施清单见 [计划](student-photos-report-v2-plan.md)。

## 教师操作

在学生管理中点击“编辑学生”，点击带上传图标的蓝色“上传照片”按钮选择 JPG/PNG，预览后点击“保存照片”。已有照片或正在预览新照片时，入口改为“更换照片”；按钮在窄屏撑满可用宽度，点击高度至少 44 像素，支持键盘激活。原生文件输入隐藏，由按钮打开文件选择器；选图后显示保存步骤提示。原图最大 2MB；浏览器按比例缩小至最长边 512 像素，透明区域填白，再转换为 JPEG，上传产物最大 256KB。新学生先保存资料，再从编辑入口上传照片。

照片单独保存，关闭学生编辑弹窗不会撤销已经保存的照片。选择但未保存的预览不影响列表。上传失败可重试，原照片保留；移除需在项目内弹窗确认。无照片或列表图片加载失败时，显示原有姓名首字与图标。弹窗支持 Escape、焦点恢复及窄屏滚动；照片操作过程中禁止重复提交和保存学生资料。

## 接口与保存

学生对象增加 `photo?: string | null`。持久化列为 `student_students.photo MEDIUMTEXT NULL`，存储限制后的 JPEG Data URL。

| 接口                                                     | 请求                          | 结果                            |
| -------------------------------------------------------- | ----------------------------- | ------------------------------- |
| `POST /classes/:classroomId/students/:studentId/photo`   | multipart 字段 `file`，仅一张 | 更新后的学生对象                |
| `DELETE /classes/:classroomId/students/:studentId/photo` | 无正文                        | 更新后的学生对象，照片为 `null` |
| 现有班级查询                                             | 现有参数                      | 学生对象包含照片                |

Web 使用现有 `/api/classes` 同源代理与 HttpOnly Cookie 认证。服务端独立解码图片，检查 JPG/PNG 实际格式与 MIME 一致、可解码、最长边不超过 512 像素、单帧、实际字节与声明一致及最大 256KB。服务端再转 JPEG，去掉元数据，限制最终存储大小。Multer 阈值为业务上限加一字节，保证恰好 256KB 可上传；超限返回 413，缺少文件、错误字段、多文件或图片内容无效返回 400。

上传和删除都检查当前教师、班级及学生归属，不可见班级或学生返回 404。图片和照片更新失败时不写入新照片。普通学生 PATCH 只接受资料字段，无法写入照片或任意外部 URL。

班级聚合保存与照片更新共用班级行事务锁。聚合保存重写学生明细前，读取锁内最新照片并保留；照片更新仅修改目标学生的照片，不更新姓名、学号和分组。这样较早打开的资料表单不会覆盖并发上传的照片。

## 报告规则

首次生成 v2 时，按当前教师与班级匹配学生管理资料，将对应学生照片保存为 `snapshot.studentPhoto`。优先匹配学生 ID，兼容宠物积分的教师前缀和旧 ID；学号兜底同样限定教师与班级。无法匹配资料或没有照片时保存 `null`。

报告正文接口从快照派生 `content.studentPhoto`。普通草稿编辑不能覆盖；发布、重新生成和历史恢复使用版本内照片。历史正文去掉该派生字段，图片只在版本快照中保存一次。学生管理换照片不会改写旧报告；旧报告缺少字段时按无头像处理，新生成报告使用当前照片。

圆形头像显示于 v2 蓝紫色标题区右侧，桌面 128 像素、窄屏 72 像素，白色边框与居中裁切，不拉伸图片。头像与两张课堂照片分别显示：v2 课堂照片及说明放在蓝紫色标题区下方的白色区域、课堂表现之前；单图保持单图区，双图并排，无照片时不显示图片区或留空占位。白色照片区的说明使用深色文字，图片保持比例。原版照片位置沿用标题区。共用 `LearningReportView` 保证预览、家长页与导出布局一致；导出等待报告内图片完成加载，失败或 10 秒超时提供重试错误，不生成缺少头像的图片。

v2 的“课堂表现”仅在报告任一课堂照片位置有图时显示，位于课堂照片之后、成长总结之前；两张课堂照片都为空时，整个区块隐藏，不留标题、评价或占位提示。旧单图字段兼容此判断，学生头像独立显示；保留分学科评价、空学科提示以及旧未分学科评价。评价来源和录入规则不变，不使用照片、积分或教学内容推断评价。

照片随有效的报告分享链接可见；没有新增公开学生查询接口，失效链接沿用现有访问拒绝。照片不进入 AI 请求。报告和流程列表仍只返回摘要，不加载图片版本正文。

## 部署

1. 备份数据库，更新依赖（新增固定版本 `sharp@0.34.5`，使用对应部署平台的原生可选依赖）。
2. 构建 Backend，执行 `pnpm --filter ClassRoomToolkitBackend migration:run`，应用 `20261013000000-add-student-photo`。此命令会运行尚未执行的迁移，应先核对迁移列表。
3. 同步部署 Backend、Worker 与 Web，检查学生查询/上传以及报告生成、分享和导出。没有新环境变量或对象存储配置。
4. 应用回退时保留新增可空列与照片；迁移 `down` 不删列，不重建数据库。此前应用读取时忽略照片列。

当前应用数据库已在备份后执行学生照片迁移，加载失败已修复；正式部署按上述步骤执行。具体验收与当前库修复结果记录在计划文件中。
