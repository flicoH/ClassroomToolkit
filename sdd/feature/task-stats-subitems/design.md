# 任务统计：内容子项与统计页调整

- 分支：`feature/task-stats-subitems`
- 范围：任务统计，包含可操作原型（[demo.html](demo.html)）、Web 界面和服务端持久化。

## 现状与目标

现有任务保存班级名称和学生名单快照；虽然表单已有 2/3/4 态选项，点击学生和统计汇总仍使用固定三态「未完成、已完成、需订正」。统计页头像目前显示姓名首字，卡片宽屏也未达到四列。本次让状态任务支持按子项统计，并统一手动统计的三态顺序和颜色。分数任务保留现有计分流程，也采用统计页头像和卡片布局调整。

## 创建与编辑

- 创建状态任务时，在任务名称下增加「任务内容」区域。教师可添加、删除并排序草稿中的子项，例如“订正第 1 题”“完成阅读记录”。留空即为手动状态任务。子项仅有名称，去除首尾空白后须为 1–128 字符；空白行或同名项提示修改，保留表单草稿。提交顺序即显示顺序，后端生成稳定 ID。
- 新任务沿用所选班级的学生名单快照；子项初始均未勾选。若所选班级已不存在或不可访问，提示重新选择。空班级可创建，统计显示 0。
- 状态任务固定使用三种状态，创建界面显示状态和颜色说明。
- 子项内容和顺序在创建时确定。带子项任务可编辑标题。

## 状态与统计口径

手动轮转顺序为已完成（绿）→ 待改正（红）→ 未完成（灰）。

循环到末尾后回到第一项。无子项任务可手动轮转或通过现有接口直接设置允许的状态。带子项任务由后端按该学生的勾选数派生：

| 勾选情况 | 状态 |
| --- | --- |
| 全部未勾选 | 未完成（灰） |
| 全部勾选 | 已完成（绿） |
| 只勾选部分 | 待改正（红） |

带子项任务的总体状态以勾选结果为准。

人数、筛选项、底部统计和任务列表完成率使用后端同一套口径：按启用的状态汇总整个任务名单，搜索和筛选只改变可见学生；完成率为已完成人数除以名单人数，沿用四舍五入，空名单为 0%。

## 开始统计界面

- 从新建、编辑和详情页点击「返回任务列表」均回到任务列表。创建成功后进入新任务详情。
- 详情卡片按参考图纵向布局。顶部显示圆形头像、姓名、学号、任务名称和状态。分隔线下显示「任务内容子项」、已勾选数与总数。勾选行用浅绿色和删除线表示完成，状态保留文字。底部全班进度随内容滚动，显示完成率、各状态人数、百分比与进度条。
- 保留原定宽屏四列卡片，在中等屏幕可显示参考图中的三列，窄屏减少列数。子项名称可换行，复选框读屏名称包含学生和子项。
- Web 从当前教师可访问的班级数据按学生 ID 取照片，并复用学生管理的头像组件。缺图、加载失败或学生已移除时显示姓名首字占位。任务仍读取创建时保存的名单和姓名。

- 勾选保存期间防止同一学生重复提交，服务端确认后刷新该学生状态和任务摘要；保存失败保留上次确认结果，显示可重试提示。不同学生并行保存时，仅合并该响应对应的学生。学生因状态变化退出当前筛选时，界面更新筛选结果和计数。

## 日期范围统计与任务列表进度

- 任务列表顶部增加「统计」。打开后可填写开始和结束日期，按任务创建日期即时筛选，包含起止当天。两项留空显示全部，单侧留空表示该侧不限。开始晚于结束时显示校验提示，范围无任务时显示空状态。
- 班级筛选默认「全部班级」，选项来自任务记录中的班级名称。班级与日期取交集，范围汇总、各任务及学生明细使用同一筛选结果。已改名或删除的班级仍可按历史任务记录中的名称查看，名称相同的记录归为同组。
- 范围汇总显示任务数、去重学生数、三态次数及完成率。一次任务分配指一名学生在一项任务中的记录，同一学生参加不同任务时分别计数。完成率使用已完成次数除以总分配次数，四舍五入到整数。任务或范围内没有学生记录时完成率为 0%。
- 各任务显示班级、创建日期、完成率及三态人数。任务列表的每张任务卡也显示已完成数、总人数、完成率、进度条和三态人数，数据与详情一致。
- 学生按学生 ID 汇总，使用范围内最新任务的姓名和学号快照作为标题。同名学生分别统计。展开学生可查看各任务的班级、日期、总体状态、已记录得分和逐项勾选情况。只有任务名单中的学生计入该任务。
- 日期范围决定纳入哪些任务，统计展示这些任务当前已保存的状态。统计和明细为只读，复用现有教师权限下的 `GET /task-stats` 响应，在 Web 端计算。本次范围统计随 Web 发布，无新增 API、配置或迁移。

## 接口、数据与权限

| 接口 | 契约 |
| --- | --- |
| `POST /task-stats` | 可带 `items: [{ title }]`，省略或传空数组保持手动模式。带子项时由后端验证教师拥有所选班级，并基于该班级生成学生快照；请求使用 `classId` 指定班级，不信任客户端传入的学生名单或初始状态。 |
| `GET /task-stats` | 保留列表和 `summary` 结构，按任务的有效状态集合统计。 |
| `GET /task-stats/:taskId` | 返回有序 `items: [{ id, title }]`、每位学生的 `checkedItemIds` 和 `status`；无子项返回空数组。 |
| `PATCH /task-stats/:taskId/students/:studentId/items/:itemId` | 请求 `{ checked: boolean }`，按期望值写入，重复请求结果相同。返回更新后的学生 ID、状态和勾选列表。 |
| `POST /task-stats/:taskId/reset` | 由教师确认后重置当前任务进度，返回任务详情。 |
| 现有任务编辑及手动状态接口 | 保留路由。非法字段、类型或状态返回 400；与当前任务模式或已有状态冲突返回 409。任务、学生、子项不属于当前教师或不在同一任务内时返回 404；未认证沿用现有认证行为。 |

任务表新增可空 JSON 列 `items`，保存有序子项和稳定 ID。任务学生表新增可空 JSON 列 `checked_item_ids`，保存已勾选的 ID。创建任务与名单写入同一事务。勾选时校验子项属于教师名下的任务，再按教师、任务及学生查找并锁定记录。更新只影响该学生。总体状态由勾选派生，手动状态继续用原字段保存，待改正对应旧数据库值「需订正」。

历史状态任务统一按三态展示。「需订正」在读取时显示并统计为「待改正」。带子项任务没有历史勾选回填。分数任务保留原有状态和统计口径。

## 部署与回滚

先发布兼容既有记录的结构迁移，再发布可同时读取新旧状态的后端，最后发布 Web。使用现有迁移流程同步两个可空 JSON 列；不在启动、迁移或发布时改写、删除或重算线上业务数据。核对隔离环境中旧任务、新任务及跨教师访问后，再开放新写入。回滚保留新增列；新数据写入后，后端只能回滚到能够读写子项及勾选结果的兼容版本，旧 Web 若无法查看或操作新任务则需保持新版界面。Web 和 Backend README 记录操作、接口和发布顺序。

## 验收与回归计划

| 场景 | 预期 |
| --- | --- |
| 创建无子项、一个子项、多个子项任务 | 无子项时手动轮转；一个或多个子项时按勾选统计；三种情况均显示三态。提交顺序刷新后保持。 |
| 子项与班级校验 | 空白、超长、重复子项或非法状态被拒绝；班级失效时保留草稿，跨教师无法读写。 |
| 手动轮转、直接设置 | 按三态顺序循环，提交三态以外的值时返回 400。 |
| 单个学生逐项勾选与取消 | 从零项到部分、全部，再取消至部分和零项，分别验证灰、红、绿及返回路径；两个学生彼此独立；刷新后保持。 |
| 持久化与错误处理 | 重发勾选请求不产生重复记录；保存失败保留上次确认结果；并发更新不同学生不回退；拒绝其他任务的子项和学生 ID。 |
| 汇总与历史兼容 | 搜索、筛选不改变全班统计；空名单为 0%；旧「需订正」正确映射，历史两态异常记录仍可见；分数任务回归。 |
| 头像和布局 | 有头像显示照片，无头像、图片失效、学生已移除均有占位；宽屏四列、窄屏换列；卡片上下布局、底部汇总及键盘勾选可用。 |
| 日期范围统计 | 同日筛选包含边界任务，反向日期提示校验，班级与日期组合筛选无匹配时显示空状态。跨任务按分配次数计数，按学生 ID 展开明细。 |
| 任务列表进度 | 每项任务显示与详情一致的完成率及三态人数。 |
| 返回导航 | 新建、编辑及详情返回任务列表，创建成功进入详情。 |
| 部署验证 | 在隔离数据库运行迁移，核对旧业务数据没有被重写；验证兼容版本能读新旧任务。 |

## 已确认增量：待提交、待改正操作与排行榜

上文记录初版范围。本节更新带子项任务的状态、操作和统计行为。

### 带子项任务的四种状态

无子项任务沿用「已完成」（绿）、「待改正」（红）、「未完成」（灰）和现有手动轮转。带子项任务增加黄色「待提交」，状态按以下优先级计算。

| 条件 | 显示状态 |
| --- | --- |
| 教师标记待改正，且至少一项已勾选 | 待改正（红） |
| 所有子项已勾选 | 已完成（绿） |
| 至少一项已勾选，且还有未勾选项 | 待提交（黄） |
| 所有子项均未勾选 | 未完成（灰） |

带子项任务在任务列表卡片、详情筛选与底部统计中显示四态人数，含人数为 0 的状态。日期范围统计在纳入带子项任务时显示「待提交」，并在对应的任务汇总和学生明细同步展示。完成率仍为「已完成」记录占比，红色「待改正」即使所有子项已勾选，也不计入总体完成率。

### 学生卡片右上角操作

按钮位于参考图蓝框处。无子项或零勾选时隐藏。其余情况按下表操作。

| 当前条件 | 按钮 | 保存结果 |
| --- | --- | --- |
| 有勾选且未标记待改正 | 待改正 | 保留现有勾选，标记为红色「待改正」 |
| 已标记待改正 | 已完成 | 一次勾选所有子项并清除待改正标记，状态变为绿色「已完成」，按钮恢复为「待改正」 |

教师仍可逐项修改勾选。已有待改正标记时，只要仍有任何勾选就保留红色状态；取消最后一个勾选时清除标记并回到灰色。任务重置同时清除勾选和待改正标记。保存期间暂停该学生的勾选与按钮操作，失败时保留上一次已保存状态并提示重试。

### 任务详情排行榜

详情工具栏增加「排名」，打开弹窗，默认标题为「完成排行榜」。每行显示排名、姓名、学号、总体状态和子项完成数。以当前任务全体学生为范围，使用服务器已保存的勾选结果。

- **完成排行榜**按已勾选子项数从多到少排列，纳入至少勾选一项的学生。这是子项完成程度排名，因此「待提交」和「待改正」也可上榜，行内保留状态标签。
- 在弹窗标题下点击「未完成任务」切换至「未完成排行榜」，按未勾选子项数从多到少排列，纳入至少一项未勾选的学生。点击同一位置的「完成任务」切回。
- 无子项任务按总体状态排行。完成榜纳入「已完成」，未完成榜纳入「未完成」，各榜内并列。
- 同分并列，下一名按实际位置编号，例如 1、1、3。同分者按学号显示，学号相同按稳定的学生 ID 排序。无上榜记录时展示空状态。弹窗支持可见关闭按钮、Esc 和窄屏滚动。

### 任务列表排行榜

任务列表顶部新增独立的「排行榜」入口。复用统计页的班级与日期筛选口径，默认全部班级、日期不限。按任务记录中的班级名称和创建日期取交集，包含起止当天，展示纳入任务的当前已保存状态。

| 榜单 | 排名指标 | 上榜条件 |
| --- | --- | --- |
| 完成排行榜 | 按学生处于「已完成」的任务数降序 | 至少有一项「已完成」 |
| 未完成排行榜 | 按学生处于「未完成」的任务数降序 | 至少有一项「未完成」 |

按学生 ID 汇总，每项任务名单中的该学生记录计一次。展示排名、姓名、学号、对应状态任务数和总分配数。黄色「待提交」和红色「待改正」归入各自的统计状态，在这两个榜单中不加分。默认显示完成榜，在榜单顶部切换完成和未完成，切换时保留筛选，同分规则与详情榜一致。日期无效时提示修正，范围内无任务或无人上榜时分别提示。

两个榜单共用名次、学生和进度三列。顶部说明当前任务或班级范围，切换按钮显示当前选中状态，列头标明统计的是子项还是任务，并显示上榜人数。每行用数值和进度条展示对应数量占比。详情弹窗内长名单独立滚动，切换按钮和右上角的 × 关闭图标保留在名单上方。窄屏优先保留姓名、学号和统计值。

### 接口、存储与发布

- 通过结构迁移 `20261116000001-add-task-stats-correction` 在任务学生记录增加可空的 `needs_correction` 标记。历史记录空值视为未标记，带子项的历史部分勾选按新规则读取为「待提交」，无需回填或重算。历史无子项的红色状态仍按原值读取。
- 新增 `PATCH /task-stats/:taskId/students/:studentId/review`，请求 `{ action: "requestCorrection" | "complete" }`，返回学生 ID、总体状态、勾选 ID 和待改正标记。按期望结果写入，支持安全重试；「已完成」操作在同一事务中更新勾选与标记。逐项勾选和重置同步维护标记。失效的任务状态或零勾选时标记待改正返回 409，非法参数返回 400，越权或不属于该任务返回 404。
- 列表、详情和操作响应统一返回服务端计算的状态；前端汇总和排行使用该状态，详情的子项排名使用有效勾选数。排行榜复用现有教师权限下的列表与详情数据。
- 先执行只新增可空列的结构迁移，再发布后端和 Web。回滚保留新增列；已有待改正标记后，回退版本需能读取并保护该标记。发布不改写已有业务记录。

### 增量验收

| 场景 | 预期 |
| --- | --- |
| 零勾选、部分、全部勾选 | 依次显示灰色「未完成」、黄色「待提交」、绿色「已完成」，任务列表对应人数同步变化 |
| 卡片右上角按钮 | 零勾选隐藏；标记红色时保留勾选；点「已完成」后全部勾选并变绿；刷新保持结果 |
| 取消勾选、重置和失败 | 取消最后一项或重置清除标记；失败时保留已保存状态；并发写入及重复请求结果一致，跨教师或跨任务写入被拒绝 |
| 详情榜切换 | 例如 3/3、2/3、0/3，完成榜按 3、2 排列，未完成榜按剩余 3、1 排列；覆盖并列与空榜 |
| 跨任务榜切换 | 班级与日期同时生效，起止当天计入；完成榜按绿色任务数，未完成榜只按灰色任务数，红黄状态不计入榜单指标 |
| 兼容和部署 | 历史部分勾选读成待提交，历史无子项手动状态照常显示；隔离数据库迁移后原记录保持 |

## AI 学期报告：数学作业完成情况

- AI 学期报告及同一工作台的 AI 阶段汇总（含自定义日期）在执行生成时，按所选生成区间读取当前教师名下该学生的任务分配。沿用任务创建日期，按北京时间纳入起止当天。按学生稳定 ID 匹配，兼容教师前缀与积分档案逻辑 ID。同一任务只计一次。
- 只计任务统计中的「已完成」与「未完成」，「待提交」和「待改正」不计入两个数字或进度条分母。任务记录没有学科字段，因此依据日期和学生筛选其任务，标题固定为「数学作业完成情况」。
- 数字在生成时保存到报告 JSON 快照 `homeworkProgress: { completed, unfinished }`。该字段由服务端计算，随报告详情及已发布报告的内容返回，只公开本学生两个汇总数。AI 正文、草稿编辑和家长端都不能改写统计；已有报告未保存该字段时不展示。若读取失败，沿用 AI 学期报告生成失败和重试流程。
- 「学习习惯与能力成长总结」在「综合画像理解」之后显示跨两列的进度条，左侧绿色「已完成」和右侧红色「未完成」各显示数量。已完成和未完成均为 0 时隐藏数学作业区块。预览、家长分享页及长图复用同一组件。
- 复用现有任务表和报告 JSON 字段，无新增接口、配置或迁移。上线不回填、不更新已有报告。验收覆盖日期边界、教师与学生隔离、红黄状态排除、空统计、报告快照和全宽显示。
